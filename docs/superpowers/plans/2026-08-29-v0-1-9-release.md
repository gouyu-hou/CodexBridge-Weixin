# CodexBridge Weixin v0.1.9 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to execute this release plan in the current session. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge the completed optimization roadmap into `main` and publish the verified Windows release as `v0.1.9` to `gouyu-hou/CodexBridge-Weixin`.

**Architecture:** Use the repository-owned release automation documented in `docs/RELEASE_PROCESS.md`. The automation aligns `package.json` and `package-lock.json`, runs the complete release gate, builds and smoke-tests the NSIS package, creates the release commit and tag, atomically pushes `main` plus `v0.1.9` to `gouyu`, and verifies the GitHub Release before publishing it.

**Tech Stack:** Git, npm, Node.js release automation, electron-builder/NSIS, GitHub CLI.

## Global Constraints

- Publish only to remote `gouyu`, repository `gouyu-hou/CodexBridge-Weixin`.
- Target version is exactly `0.1.9`; do not reuse or overwrite an existing tag or release.
- Do not force-push.
- Preserve all existing user changes and stop before merging if either worktree is dirty.
- Run the complete release gate and packaged smoke test before publication.
- Publish exactly the installer, blockmap, and `latest.yml` verified by the release automation.
- If publication fails after the atomic push, use the recorded `--resume` workflow rather than rerunning `--publish`.
